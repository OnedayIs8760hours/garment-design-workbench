# 模板与资源目录规范

## 目的

本规范用于约束 SDS Design 当前前后端工作区中的模板元数据、浏览器静态资源、3D 模型、Photoshop 脚本和相关文档的放置方式。

所有服装品类必须使用同一个英文品类目录名串联模板元数据、浏览器静态资源、3D 模型和导出引用。不要再用尺码 ID、临时导出名或 CLO 文件名作为 public 目录名。

## 当前项目结构

```text
SDS-design/
  frontend/
    src/
      components/
      pages/
      styles/
      App.jsx
      model.js
      model.test.js
      designStore.js
      config.js
    templates/
      index.js
      <category>/
        <templateId>.template.json
        <templateId>.uv_mapping.json
    public/
      templates/
        <category>/
      models/
        <category>.glb
  backend/
    src/main/java/com/sdsdesign/
    src/test/java/com/sdsdesign/
  photoshop/
    *.jsx
    *.ps1
  scripts/
    *.mjs
  规范/
  项目记录/
```

目录职责：

- `frontend/src/` 存放 React 应用代码、页面、组件、状态和测试。
- `frontend/templates/` 存放可被应用 import 的模板元数据和 UV 映射。
- `frontend/public/templates/` 存放浏览器按 URL 直接加载的裁片图和遮罩图。
- `frontend/public/models/` 存放浏览器按 URL 直接加载的 GLB 模型。
- `backend/` 存放 Spring Boot API 服务，不放前端模板图片和 GLB。
- `photoshop/` 存放 Photoshop 自动化脚本和 PowerShell runner。
- `scripts/` 存放模板导入、UV 映射生成等 Node 脚本。
- `规范/` 存放长期约束文档。
- `项目记录/` 存放阶段性实现记录、原型边界和后续接入点。

## 前端源码目录

`frontend/src/` 按职责拆分：

```text
frontend/src/
  components/      # 可复用 React UI 组件
  pages/           # 页面级组件，例如 LoginPrototype.jsx
  styles/          # 页面级或主题级样式，例如 login.css
  App.jsx          # 应用入口壳和页面选择
  config.js        # 当前模板配置导出
  designStore.js   # 编辑器状态
  model.js         # 模板、订单、校验等纯逻辑
  model.test.js    # 前端自检入口
```

规则：

- 页面级组件放入 `frontend/src/pages/`。
- 通用 UI 组件放入 `frontend/src/components/`。
- 页面专属样式放入 `frontend/src/styles/`。
- 全局编辑器样式仍保留在 `frontend/src/styles.css`。
- `App.jsx` 只负责应用入口、页面选择和编辑器壳连接，不堆放大段页面 JSX。
- 不要在 React 组件中硬编码某个品类的裁片尺寸、坐标、遮罩路径或裁片 ID。

## 品类命名

品类目录使用英文 kebab-case：

- 普通橄榄球衣：`football-jersey`
- 橄榄球衣-双拼-露脐：`football-jersey-crop-top-two-tone`

模板 ID 仍保留业务尺码或模板 ID，例如 `M-2XL`、`W-M`。品类目录和模板 ID 是两个概念，不要混用。

命名关系：

```text
category = football-jersey
templateId = M-2XL
template file = frontend/templates/football-jersey/M-2XL.template.json
model file = frontend/public/models/football-jersey.glb
public asset base = /templates/football-jersey
```

## 模板元数据

模板元数据统一放在 `frontend/templates/`：

```text
frontend/templates/
  index.js
  football-jersey/
    M-2XL.template.json
    M-2XL.uv_mapping.json
  football-jersey-crop-top-two-tone/
    W-M.template.json
    W-M.uv_mapping.json
```

规则：

- `frontend/templates/index.js` 是唯一模板注册入口。
- 每个模板必须有 `*.template.json`。
- 每个支持 3D 预览的模板必须有 `*.uv_mapping.json`。
- 模板事实，包括裁片尺寸、bounds、图层名、mask 路径、guides，都只能写在模板 JSON 中。
- `config.js`、组件和 store 只能读取模板事实，不应复制模板事实。
- 新增模板后必须在 `frontend/templates/index.js` 中注册。

## Public 静态资源

浏览器直接加载的裁片图、遮罩图放在 `frontend/public/templates/<category>/`：

```text
frontend/public/templates/
  football-jersey/
    panels/
      front.png
      back.png
    masks/
      front-mask.png
      back-mask.png
  football-jersey-crop-top-two-tone/
    up-front/
      panels/
        front.png
      masks/
        front-mask.png
    up-back/
      panels/
        up-back.png
      masks/
        up-back-mask.png
```

规则：

- public 目录名必须和 `frontend/templates/<category>/` 保持一致。
- `*.template.json` 里的 `panelImage`、`maskImage` 写相对 `publicAssetBase` 的路径。
- `frontend/templates/index.js` 中每个模板定义必须配置 `publicAssetBase`，例如 `/templates/football-jersey`。
- 订单导出的 `sourceFile` 应使用 `templates/<category>/...`，不能使用旧的 `templates/M-2XL/...` 或 `templates/W-M/...`。
- 裁片图和遮罩图属于浏览器静态资源，不要放进 `frontend/src/`。
- 不要把模板图片写成绝对本地路径，例如 `S:\...` 或 `C:\...`。

## 3D 模型

GLB 模型放在 `frontend/public/models/`，文件名使用品类英文名：

```text
frontend/public/models/
  football-jersey.glb
  football-jersey-crop-top-two-tone.glb
```

规则：

- `frontend/templates/index.js` 中 `defaultModelUrl` 必须指向 `/models/<category>.glb`。
- 不再使用临时名，例如 `soccer-new-rename.glb`、`soccer-women.glb`。
- `*.uv_mapping.json` 的 `source_model` 应与 public 模型文件名一致。
- 多个模板共用品类模型时，可以共用同一个 `<category>.glb`，但 UV 映射仍按模板 ID 独立保存。

## Photoshop 相关目录

Photoshop 自动化脚本统一放在 `photoshop/`：

```text
photoshop/
  export-psd-json.jsx
  restore-front-smart-object.jsx
  restore-panels-smart-objects.jsx
  run-restore-front.ps1
```

规则：

- `.jsx` 存放 Photoshop ExtendScript 逻辑。
- `.ps1` 存放本地执行 runner。
- Web 订单 JSON 可能只引用图片文件名，不保证嵌入图片数据。
- 为保证 Photoshop 还原可靠，订单 JSON 旁应保留源图片，或放在同级 `assets/` 目录，或使用包含素材的 ZIP 导出。
- Photoshop 脚本读取模板和订单时，应使用导出 JSON 中的 `sourceFile`、图层名和裁片 ID，不要依赖临时目录名。

## 后端目录边界

`backend/` 当前是 Spring Boot API 服务：

```text
backend/
  src/main/java/com/sdsdesign/
  src/main/resources/application.yml
  src/test/java/com/sdsdesign/
```

规则：

- 后端不保存浏览器静态模板图片和 GLB。
- 后续如果接入模板管理 API，后端只负责数据服务、上传、权限和持久化，不直接替代 `frontend/templates/` 的前端模板注册职责。
- 后端测试放入 `backend/src/test/java/com/sdsdesign/`。
- 后端变更后运行 `mvn test`。

## 脚本目录

仓库根目录 `scripts/` 存放模板处理脚本，例如：

```text
scripts/
  import-clo-template.mjs
  generate-glb-uv-mapping.mjs
```

规则：

- 脚本输入可以来自本地 CLO/Photoshop 导出目录。
- 脚本输出必须落到规范目录：`frontend/templates/<category>/` 和 `frontend/public/templates/<category>/`。
- 脚本不应把临时源目录结构带入 public 目录。
- 脚本生成后必须跑前端测试确认模板注册、资源路径和 UV 映射有效。

## UV 映射生成

从 GLB 生成 UV 映射：

```powershell
node scripts/generate-glb-uv-mapping.mjs `
  --model frontend/public/models/football-jersey-crop-top-two-tone.glb `
  --template frontend/templates/football-jersey-crop-top-two-tone/W-M.template.json `
  --out frontend/templates/football-jersey-crop-top-two-tone/W-M.uv_mapping.json
```

生成后必须在 `frontend/templates/index.js` 中 import 并注册到对应模板的 `uvMapping`。

## CLO 模板导入

从 CLO/Photoshop 分裁片导出目录导入 Web 模板：

```powershell
node scripts/import-clo-template.mjs `
  --source "S:\path\to\参数数据" `
  --template-id W-M `
  --category football-jersey-crop-top-two-tone `
  --panel-order up-front,up-back,under-front,under-back,left-sleeve,right-sleeve,collar
```

脚本输出：

- `frontend/templates/<category>/<templateId>.template.json`
- `frontend/public/templates/<category>/...`

如果该模板支持 3D 预览，再运行 UV 映射生成脚本。

## 规范和项目记录

长期规则放入 `规范/`，阶段性记录放入 `项目记录/`：

```text
规范/
  模板与资源目录规范.md
  前端设计规范.md

项目记录/
  2026-08-13-login-prototype.md
```

规则：

- 会长期约束后续开发的内容写入 `规范/`。
- 一次原型、一次导入、一次迁移的过程和边界写入 `项目记录/`。
- 记录文件名建议使用 `YYYY-MM-DD-topic.md`。
- 规范更新应跟随代码结构变化同步提交。

## 新增品类 Checklist

1. 先确定英文 category slug。
2. 将模板 JSON 放到 `frontend/templates/<category>/`。
3. 将裁片图和遮罩放到 `frontend/public/templates/<category>/`。
4. 将 GLB 放到 `frontend/public/models/<category>.glb`。
5. 生成 `frontend/templates/<category>/<templateId>.uv_mapping.json`。
6. 在 `frontend/templates/index.js` 注册 `template`、`uvMapping`、`publicAssetBase`、`defaultModelUrl`、`defaultPanelId`。
7. 在 `frontend/src/model.test.js` 添加路径和 UV 映射断言。
8. 进入 `frontend/` 后运行 `npm test` 和 `npm run build`。
9. 如果导出 JSON 会交给 Photoshop 还原，运行对应 `photoshop/run-*.ps1` 做本地验证。
10. 如果目录结构或导出约定发生变化，同步更新 `规范/模板与资源目录规范.md`。

## 变更检查

提交涉及模板或资源目录的改动前检查：

- `frontend/templates/<category>/` 与 `frontend/public/templates/<category>/` 是否同名。
- `publicAssetBase` 是否指向 `/templates/<category>`。
- `defaultModelUrl` 是否指向 `/models/<category>.glb`。
- `sourceFile` 是否使用 `templates/<category>/...`。
- React 组件是否没有新增硬编码裁片事实。
- `npm test` 是否通过。
- `npm run build` 是否通过。
