# 在线裁片定制 Web 端实现方案

## 1. 项目背景

当前定制产品的设计流程中，设计美工先在成衣效果图 PSD 上完成视觉设计，再由订单美工根据效果图，将图案、文字、号码等内容重新放置到生产裁片图中。

该流程存在明显的信息转换误差：

- 效果图中的图案经过透视、弯曲、褶皱和遮挡后，订单美工难以准确还原其在平面裁片上的真实位置；
- 图案尺寸、中心点、旋转角度、层级等信息没有被结构化保存；
- 不同订单依赖订单美工个人经验，结果稳定性较差；
- 设计效果图和生产裁片图之间缺少统一的数据源；
- 同一设计可能需要多次人工调整，增加时间成本和返工概率。

因此，Web 端应当把“裁片设计数据”作为唯一设计源。

用户或内部设计人员直接在单个裁片上完成设计，系统自动记录所有素材的位置和属性。右侧只提供快速近似预览，最终真实效果图和生产 PSD 由后续 Photoshop 脚本根据 JSON 数据生成。

---

## 2. 核心目标

Web 端第一阶段需要实现以下目标：

1. 用户可以选择产品和对应模板；
2. 用户可以逐个编辑产品的不同裁片；
3. 用户可以向裁片中添加图片、文字、号码、Logo 和预设素材；
4. 用户可以移动、缩放、旋转和调整素材层级；
5. 系统可以准确记录每个素材在裁片中的位置和属性；
6. 用户可以在右侧看到整体产品的快速近似预览；
7. 用户可以切换不同裁片继续设计；
8. 系统可以保存、恢复和继续编辑设计；
9. 所有裁片完成后，系统生成标准设计 JSON；
10. JSON 可以供后续 JSX 脚本生成真实效果图 PSD 和生产裁片 PSD。

---

## 3. 方案总览

整个 Web 页面采用左、中、右三栏结构。

```text
┌────────────────┬──────────────────────────────┬──────────────────────┐
│ 左侧素材区      │ 中间裁片编辑区                │ 右侧整体预览区        │
│                │                              │                      │
│ 图片素材        │ 当前单一裁片                  │ 正面整体效果          │
│ 文字工具        │ 裁片轮廓                      │ 背面整体效果          │
│ 号码工具        │ 安全区                        │ 快速近似渲染          │
│ Logo 素材       │ 出血区                        │                      │
│ 预设图案        │ 素材编辑                      │                      │
└────────────────┴──────────────────────────────┴──────────────────────┘
```

系统中的数据流为：

```text
左侧选择素材
    ↓
中间放置到当前裁片
    ↓
系统记录素材属性
    ↓
右侧更新快速预览
    ↓
切换其他裁片继续设计
    ↓
保存全部裁片设计
    ↓
生成设计 JSON
    ↓
后续 JSX 读取 JSON
```

## 4. 设计原则

### 4.1 裁片数据是唯一设计源

系统必须以中间裁片编辑区中的设计数据为准。

右侧整体效果图只是快速预览结果，不能反向修改裁片数据，也不能作为最终生产依据。

```text
裁片设计数据
    ├─ 生成右侧快速预览
    ├─ 生成订单设计 JSON
    ├─ 生成真实效果图 PSD
    └─ 生成生产裁片 PSD
```

### 4.2 快速预览和真实效果分离

右侧预览只需要满足：

- 大致位置正确；
- 大小比例接近；
- 颜色接近；
- 能看出整体搭配；
- 操作时更新流畅。

右侧不要求完全复刻 Photoshop 中的：

- 复杂褶皱；
- 高级混合模式；
- 精细置换；
- 真实布料纹理；
- 精确透视变形；
- 最终印刷效果。

真实效果由用户完成设计后，交给后续 Photoshop 流程生成。

### 4.3 坐标与显示尺寸解耦

浏览器中裁片显示尺寸可能因屏幕和窗口大小变化，但保存的数据不能依赖当前像素。

系统应使用逻辑坐标或相对坐标保存设计。

例如：

```json
{
  "centerX": 0.5,
  "centerY": 0.42,
  "width": 0.36,
  "rotation": 0
}
```

其中：

- `centerX = 0.5` 表示元素中心位于裁片宽度的 50%；
- `centerY = 0.42` 表示元素中心位于裁片高度的 42%；
- `width = 0.36` 表示元素宽度为裁片逻辑宽度的 36%。

## 5. 页面结构

## 5.1 顶部区域

顶部主要用于显示当前订单和模板信息。

建议包含：

- 产品名称；
- 模板名称；
- 当前尺码；
- 当前设计状态；
- 撤销；
- 重做；
- 保存草稿；
- 生成最终设计；
- 返回商品页。

示例：

```text
圆领短袖 T 恤 / 模板 V12 / 尺码 2XL / 已保存
```

## 5.2 左侧素材区

左侧素材区用于管理和添加设计元素。

建议分为以下分类：

### 用户上传

- 上传图片；
- 最近上传；
- 当前订单素材；
- 图片清晰度提示；
- 原始素材状态。

### 图片素材

- 公司预设图片；
- 装饰图案；
- 背景纹理；
- 常用素材分类；
- 搜索素材。

### 文字

用户点击后创建一个文字元素。

文字属性包括：

- 文字内容；
- 字体；
- 字号；
- 颜色；
- 描边颜色；
- 描边宽度；
- 字间距；
- 行间距；
- 对齐方式；
- 透明度；
- 弯曲类型；
- 弯曲强度。

### 号码

号码可以作为独立元素类型，也可以复用文字元素。

号码属性包括：

- 号码内容；
- 号码字体；
- 填充颜色；
- 描边颜色；
- 描边宽度；
- 双层描边；
- 固定比例；
- 最大位数。

### Logo

- 品牌 Logo；
- 队徽；
- 赞助商图标；
- 用户上传 Logo；
- 预设尺寸规则。

### 预设组合

可以提供常用设计组合：

- 背面姓名 + 号码；
- 左胸 Logo；
- 袖口号码；
- 正面大图；
- 姓名弧形排版；
- 常见球队排版。

用户选择组合后，系统一次添加多个已配置好的元素。

## 5.3 中间裁片编辑区

中间区域是 Web 端最重要的部分。

### 裁片切换

需要提供清晰的裁片选择入口，例如：

```text
前片 | 后片 | 左袖 | 右袖 | 领口 | 其他
```

每个裁片应显示状态：

- 未开始；
- 编辑中；
- 已完成；
- 存在警告；
- 存在错误。

### 裁片显示内容

中间编辑区建议显示：

- 裁片外轮廓；
- 可设计区域；
- 安全区域；
- 出血区域；
- 缝线；
- 中心线；
- 关键定位点；
- 不可打印区域；
- 当前裁片名称；
- 裁片方向；
- 左右标识。

### 元素编辑能力

用户可以对素材执行：

- 添加；
- 选择；
- 移动；
- 等比缩放；
- 非等比缩放；
- 旋转；
- 复制；
- 删除；
- 锁定；
- 隐藏；
- 调整层级；
- 水平翻转；
- 垂直翻转；
- 居中；
- 水平对齐；
- 垂直对齐；
- 吸附中心线；
- 吸附安全区；
- 吸附关键点。

### 元素属性面板

当用户选择某个元素时，应显示对应属性。

图片元素：

- 素材名称；
- 原始尺寸；
- 当前宽高；
- 坐标；
- 旋转角度；
- 透明度；
- 裁切方式；
- 锁定比例；
- 清晰度状态。

文字元素：

- 文字内容；
- 字体；
- 字号；


## 5.4 右侧整体预览区

右侧用于展示整体产品的近似视觉效果。

### 预览目标

右侧应帮助用户判断：

- 图案是不是过大；
- 图案位置是否合适；
- 正背面是否协调；
- 左右袖是否统一；
- 姓名和号码是否协调；
- 整体颜色搭配是否合理。

### 预览模式

建议至少提供：

- 正面；
- 背面；
- 左侧；
- 右侧；
- 正背面对比。

第一阶段可以只实现正面和背面。

### 右侧预览生成方式

每个裁片在中间编辑完成后，系统生成一张低分辨率裁片预览纹理。

右侧将各裁片预览纹理：

1. 放置到预设区域；
2. 进行简单缩放、旋转或透视；
3. 与产品底图叠加；
4. 再叠加阴影、高光和衣服细节；
5. 得到快速近似效果。

右侧预览不保存为设计事实，所有元素的位置仍以中间裁片数据为准。

### 预览提示

页面应明确提示：

> 当前为快速预览，最终真实效果以高清效果图为准。

## 6. 模板数据

每个商品款式需要对应一份 Web 模板配置。

模板配置应包含：

- 模板 ID；
- 模板版本；
- 产品类型；
- 支持的尺码；
- 包含哪些裁片；

- 安全区；

- 不可打印区；

## 8. 素材管理

同一个素材需要区分预览文件和原始文件。

```text
原始素材
    用于最终 JSX 生产

预览素材
    用于 Web 编辑和右侧预览
```

素材信息至少应包含：

- 素材 ID；
- 素材类型；
- 文件名称；
- 预览文件地址；
- 原始文件地址；
- 原始宽度；
- 原始高度；
- 文件格式；
- 文件大小；
- 透明背景状态；
- 清晰度状态；
- 上传时间。

Web 端只使用预览素材进行实时操作，避免高分辨率原图影响浏览器性能。

## 9. 保存与恢复

### 自动保存

建议在以下操作后自动保存草稿：

- 添加素材；
- 删除素材；
- 移动完成；
- 缩放完成；
- 旋转完成；
- 修改文字；
- 切换裁片；
- 修改颜色；
- 修改图层顺序。

自动保存可以设置短暂延迟，避免连续操作产生大量保存请求。

### 手动保存

页面提供明显的“保存草稿”按钮。

保存成功后显示：

```text
已保存，更新时间 17:36
```

### 恢复设计

用户重新进入页面时，应恢复：

- 当前模板；
- 当前尺码；
- 当前裁片；
- 所有元素；
- 元素属性；
- 图层顺序；
- 整体颜色；
- 右侧预览；
- 校验结果。

### 版本记录

后续可以增加设计版本：

```text
版本 1：初始设计
版本 2：修改背面号码
版本 3：更换正面图案
```

第一阶段可以暂不实现完整版本管理，但数据结构中应预留版本号。

## 10. 撤销与重做

Web 编辑器必须支持撤销和重做。

建议记录以下操作：

- 添加元素；
- 删除元素；
- 移动元素；
- 缩放元素；
- 旋转元素；
- 修改文字；
- 修改颜色；
- 修改描边；
- 修改弯曲；
- 调整图层顺序；
- 切换锁定状态。

拖拽过程中不需要每一帧都记录，只在拖拽开始前和拖拽结束后分别记录状态。

## 11. 规则与校验

提交设计前，系统需要校验每个裁片。

### 图片校验

- 图片是否存在；
- 图片是否加载成功；
- 分辨率是否足够；
- 图片是否超出可设计区；
- 图片是否进入不可打印区；
- 图片是否过小；
- 图片是否透明；
- 图片是否被完全遮挡。

### 文字校验

- 字体是否可用；
- 是否存在不支持字符；
- 文字是否超出安全区；
- 姓名是否超过最大长度；
- 号码位数是否符合要求；
- 描边宽度是否合理；
- 文字颜色与底色对比是否过低。

### 裁片校验

- 必填裁片是否完成；
- 必填元素是否存在；
- 是否存在超出边界元素；
- 是否存在未完成的素材上传；
- 是否存在被隐藏但应生产的元素。

### 校验结果

校验结果分为：

- 错误：不允许提交；
- 警告：允许继续，但需要用户确认；
- 提示：不影响提交。

---

## 12. 快速预览性能要求

Web 端实时预览应以流畅为优先。

### 基本策略

- 浏览器只加载压缩后的预览素材；
- 不加载和解析 PSD；
- 不使用生产分辨率进行实时绘制；
- 只更新发生变化的裁片；
- 静态背景、阴影和高光只加载一次；
- 用户拖拽时使用较低预览质量；
- 用户停止操作后再更新清晰预览；
- 避免每次操作都导出完整图片；
- 文字输入需要限制更新频率；
- 未显示的视图不需要持续重绘。

### 预览分辨率

建议分为：

```text
交互预览：低分辨率，保证流畅
静止预览：中等分辨率，保证清晰

```

## 16. 与后续 JSX 的接口边界

Web 端只负责输出标准 JSON 和原始素材引用。

Web 端不负责：

- 打开 PSD；
- 修改 PSD 图层；
- 替换智能对象；
- 生成真实褶皱；
- 生成生产裁片；
- 保存最终 PSD。

后续 JSX 负责：

```text
读取设计 JSON
    ↓
打开对应模板 PSD
    ↓
读取每个裁片元素
    ↓
载入原始高清素材
    ↓
根据相对坐标计算 Photoshop 坐标
    ↓
设置素材大小、位置、旋转和层级
    ↓
处理文字、描边和弯曲
    ↓
生成真实效果图
    ↓
生成生产裁片 PSD
```

Web 端和 JSX 之间最重要的约定是：

- 模板 ID 一致；
- 模板版本一致；
- 裁片 ID 一致；
- 元素类型一致；
- 坐标定义一致；
- 旋转方向一致；
- 图层顺序一致；
- 字体 ID 一致；
- 颜色格式一致；
- 素材引用一致。

## 17. 验收标准

第一阶段完成后，应满足以下验收条件。

### 编辑能力

- 用户可以完成前片和后片设计；
- 图片、文字和号码可以正常编辑；
- 元素位置保存后重新进入不会发生明显偏移；
- 图层顺序保存正确；
- 撤销和重做可用。

### 数据准确性

- JSON 可以完整还原当前设计；
- 同一 JSON 在不同屏幕尺寸下显示结果一致；
- 相对坐标可正确转换为裁片坐标；
- 素材 ID 与原始文件可正确关联；
- 模板版本可追溯。

### 预览能力

- 右侧可以显示正面和背面近似效果；
- 修改当前裁片后，右侧可以及时更新；
- 预览不会影响中间裁片的准确数据；
- 页面在正常操作时保持流畅。

### 保存能力

- 设计可以保存为草稿；
- 草稿可以恢复；
- 所有裁片完成后可以生成最终 JSON；
- 校验错误时不能提交；
- 校验警告可以提示用户确认。

## 18. 最终架构结论

该 Web 端的核心不是制作一个网页版 Photoshop，而是建立一套稳定的裁片设计数据系统。

```text
中间裁片编辑区
    = 准确设计源

右侧整体预览区
    = 快速视觉参考

订单设计 JSON
    = 系统数据源

Photoshop JSX
    = 最终真实渲染与生产输出
```

最终流程为：

```text
用户设计裁片
    ↓
系统记录结构化数据
    ↓
右侧提供快速近似预览
    ↓
所有裁片完成
    ↓
生成订单设计 JSON
    ↓
JSX 根据 JSON 生成真实效果图 PSD
    ↓
JSX 根据 JSON 生成生产裁片 PSD
```

这样可以从根本上取消“订单美工根据效果图重新补板”的人工翻译过程，并保留现有 PSD 生产体系。
