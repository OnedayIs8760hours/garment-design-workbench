# 虚线辅助线数据结构与实现过程

## 目标

裁片编辑器里的虚线不是装饰，它是模板的一部分。

多品类、多尺码、多裁片时，虚线不能写死在 React 代码里，也不能靠某个固定文件名约定。每个模板包应该自己携带这些信息：

- 裁片边界线
- 中心线
- 安全区线
- 出血线
- 缝份线
- 其他工艺辅助线

前端只负责读取 `template.json` 并渲染。

## 最终存放位置

每个裁片的辅助线存放在：

```text
template.json
  panels
    front
      guides[]
```

示例：

```json
{
  "panelId": "front",
  "name": "前片",
  "size": {
    "width": 2796,
    "height": 2800
  },
  "panelImage": "panels/front.png",
  "maskImage": "masks/front-mask.png",
  "guides": [
    {
      "id": "cutline",
      "name": "裁片边界",
      "type": "path",
      "coordinateSpace": "panel-px",
      "closed": true,
      "points": [
        [0, 572],
        [40, 550],
        [80, 521]
      ],
      "style": {
        "stroke": "#0f766e",
        "strokeWidth": 2,
        "dash": [8, 6]
      }
    },
    {
      "id": "center_line",
      "name": "中心线",
      "type": "line",
      "coordinateSpace": "panel-px",
      "from": [1398, 0],
      "to": [1398, 2800],
      "style": {
        "stroke": "#94a3b8",
        "strokeWidth": 1,
        "dash": [5, 8]
      }
    }
  ]
}
```

## 字段说明

`id`：稳定机器名，例如 `cutline`、`center_line`、`safe_area`。

`name`：给界面或调试用的人类可读名称。

`type`：当前支持两种：

- `path`：多点路径，适合裁片边界、安全区、出血线。
- `line`：两点直线，适合中心线、对位线。

`coordinateSpace`：坐标系。当前统一使用 `panel-px`，也就是裁片局部像素坐标，不是浏览器像素，也不是整张 PSD 像素。

`points`：`path` 使用的点数组。

`closed`：路径是否闭合。裁片边界通常是 `true`。

`from` / `to`：`line` 使用的起终点。

`style`：渲染样式。虚线本身也应该是模板属性，不要写死在组件里。

## 为什么不用 React 写死

最初旧 demo 里虚线是代码形式：

```js
clipPath: [
  [52, 3292],
  [3288, 3292]
]
```

问题是：

- 只适合一个 demo 裁片。
- 换品类、换尺码、换 PSD 后必然错位。
- 中间编辑区和右侧预览容易各维护一套线。
- 后续 JSX 回写生产 PSD 时，Web 上看到的线和真实模板数据没有稳定关系。

所以虚线必须属于 `template.json`，由 Photoshop JSX 模板导出器生成。

## mask 和 guide 的分工

`maskImage` 负责真实裁切。

```text
masks/front-mask.png
```

它决定素材最终能显示在哪些像素内。

`guides[]` 负责显示辅助线。

它只给用户看，不应该作为最终裁切依据。

不要把二者混成一个概念：

- 裁切用 mask，像素级准确。
- 显示用 guide，轻量、可缩放、可配置样式。

## 前端实现方式

中间 Konva 画布：

1. 读取当前 `panel.guides`。
2. `line` 渲染成 Konva `Line`。
3. `path` 渲染成 Konva `Line`，`closed` 控制是否闭合。
4. 把 `panel-px` 坐标按当前 stage 尺寸缩放。
5. 样式读取 `guide.style`。

核心逻辑：

```js
function scalePoint([x, y], panel) {
  return [
    (x / panel.logicalSize.width) * stageSize.width,
    (y / panel.logicalSize.height) * stageSize.height
  ];
}
```

右侧预览：

1. 使用同一份 `panel.guides`。
2. 用 SVG 叠层渲染。
3. `line` 对应 `<line>`。
4. 闭合 `path` 对应 `<polygon>`。
5. 非闭合 `path` 对应 `<polyline>`。

这样中间和右侧不会出现两套虚线。

## JSX 导出器应该做什么

正式版本中，Photoshop JSX 模板导出器应该在导出每个裁片时同时生成：

```text
panels/front.png
masks/front-mask.png
template.json -> panels.front.guides[]
```

对于 `cutline`：

1. 从裁片透明区域或图层蒙版得到真实 alpha mask。
2. 从 alpha mask 提取外轮廓点。
3. 将轮廓点转换为裁片局部坐标。
4. 写入 `guides[].points`。

对于 `center_line`：

1. 使用裁片局部宽度的一半。
2. 写入 `[width / 2, 0]` 到 `[width / 2, height]`。

对于安全区、出血线、缝份线：

优先从 PSD 中独立命名图层导出，例如：

```text
GUIDE_front_safe_area
GUIDE_front_bleed
GUIDE_front_seam
```

不要在 Web 里猜。

## 多品类目录结构

每个品类或尺码一个模板包：

```text
public/templates/
  M-2XL/
    template.json
    panels/
      front.png
    masks/
      front-mask.png
  Kids-120/
    template.json
    panels/
      front.png
    masks/
      front-mask.png
```

前端加载哪个模板，就读取哪个模板的 `guides[]`。

## 当前踩过的坑

### 1. 旧虚线是手写坐标

旧线来自 demo 的 `clipPath`，不是当前 PSD 的真实轮廓。

现象：

- 中间画布有一条看起来像裁片边界的虚线。
- 但它和真实绿色裁片边缘不完全一致。
- 用户会误以为那是真实生产边界。

处理：

- 删除主流程中的硬编码 `clipPath`。
- 改为读取 `template.json -> guides[]`。

### 2. 右侧预览没有同步

一开始只改了中间画布，右侧仍然是 CSS 假 T 恤。

现象：

- 中间显示真实裁片。
- 右侧还是旧 T 恤轮廓。
- 同一个元素在两侧位置看起来不是同一套数据。

处理：

- 右侧也读取 `template.panels[panelId]`。
- 右侧元素同样使用相对坐标。
- 右侧辅助线同样读 `guides[]`。

### 3. 不要用临时 outline PNG 作为长期方案

曾经临时生成过：

```text
masks/front-outline.png
```

它可以显示真实边界，但不适合长期存放虚线信息。

原因：

- 样式不容易改。
- 不能表达中心线、安全区、出血线等语义。
- 多品类时会变成一堆没有结构的图片文件。
- 前端无法知道这条线代表什么。

最终方案：

- 线的语义和点位存 JSON。
- mask 只负责裁切。

### 4. 从 mask 提取路径时点顺序很重要

不能随便把所有边缘点塞进 `points`。

错误结果：

- 点很多。
- 顺序混乱。
- SVG/Konva 连线会交叉。
- 虚线可能穿过裁片内部。

正确要求：

- 点必须按轮廓顺时针或逆时针排列。
- 闭合路径最后由 `closed: true` 闭合。
- 点数量要控制，够平滑即可。

当前 demo 使用简化采样，后续 JSX 导出器应使用更稳定的轮廓追踪算法。

### 5. 点太密会拖慢渲染

每个像素一个点没有必要。

建议：

- 普通 Web 预览使用 20 到 50 px 的采样间隔。
- 曲线处可以适当加密。
- 大批量模板导出时做路径简化。

以后如果需要更精确，可以使用 Ramer-Douglas-Peucker 之类的路径简化算法。

### 6. 坐标系必须写清楚

不要混用三种坐标：

- 整张 PSD 坐标。
- 裁片局部 px 坐标。
- 浏览器 stage 坐标。

当前约定：

```text
guides[].coordinateSpace = "panel-px"
```

也就是以裁片导出的局部 PNG 左上角为 `[0, 0]`。

前端显示时再缩放到 stage。

### 7. Windows 终端编码会误导判断

PowerShell 输出中文时可能乱码，但文件本身仍然是 UTF-8。

判断文件有没有坏，不要只看终端显示。

应该用：

- 构建结果
- 测试结果
- 浏览器显示
- 明确指定 UTF-8 读取

### 8. PowerShell 图像逐像素处理很慢

用 `GetPixel()` 逐像素扫描大 PNG 很容易超时。

后续如果需要在本地处理图像：

- 小图可以临时用 `GetPixel()`。
- 大图应该用 `LockBits`。
- 正式流程最好放在 JSX 导出阶段一次性生成，不要浏览器运行时处理。

### 9. CSS mask 和 guide 不是同一件事

右侧预览现在用 CSS mask 裁切元素：

```css
mask-image: url(front-mask.png);
```

辅助线用 SVG/Konva 画。

不要试图用 guide path 代替 mask 裁切。guide 是视觉提示，mask 是像素级边界。

## 推荐的最终原则

模板包里必须保存：

```text
panelImage
maskImage
bounds
size
guides[]
```

Web 里不保存：

```text
某个品类的硬编码虚线坐标
某个固定尺码的裁片边界
某个固定 PNG 文件名作为轮廓语义
```

JSX 导出器负责生成模板事实。

Web 负责渲染和编辑。

订单 JSON 只保存用户设计元素，不保存模板虚线。
